# anvil v1 spec

术语以 `CONTEXT.md` 为准；工作方式以 anvil-k0t 的 `## Rulings` 为准。

## 1. Goal and scope

- 目标：在 Claude Code 里一次交付三项需求。**额度利用率**：长会话中途离开时 prompt 缓存不过期，回来时不误发一条要整段重建缓存的消息。**显示**：全屏下停靠在右侧的 **anvil 面板**取代 **statusline**，把缓存、用量、子 agent、自动模式拒绝、我的消息和身份信息放在一处。**英文沟通**：先写中文、译成英文再发，借此练习。
- 验收（用户在自己的终端里能看到的）：
  - A1 上下文达到阈值的会话，空闲时 anvil 自动续期缓存：离开几小时（不超过 12 小时）回来，第一条消息读到整段缓存，不用重建。
  - A2 `/anvil keepalive` 切换本会话的保活：默认开着时敲一次就不再续期，再敲一次恢复；自动开启关掉或上下文低于阈值时也能敲一次开启；新会话回到默认；`/config` 里能关掉自动开启、改阈值。
  - A3 保活自己停下时（一段空闲续满 12 小时、读数不达标、请求出错），缓存框写明原因；回来发一条消息后，下一段空闲照常保活。
  - A4 缓存已过期且上下文达到阈值时，第一条发给模型的消息被拦下，提示过期时长和重建代价，原文仍在主输入框；再按一次 Enter 正常发出。恢复一个缓存很可能已过期的会话也一样。
  - A5 全屏渲染、终端不少于 110 列时，anvil 面板常驻停靠在对话右侧，可拖动边界改宽；自上而下是缓存、用量、子 agent、自动模式拒绝、我的消息、身份栏（子 agent、自动模式拒绝在本会话有内容后才出现）；任何宽度下都不裁切、不重叠，数字变化时排版不左右跳。`/anvil panel` 在当前会话切换面板的显示和隐藏。
  - A6 面板显示 D8 列出的全部内容，数值和 Claude Code 自己报的（`/usage`、`/cost`）以及 `git status` 一致；关掉 statusline 后，它原来显示的信息都能在面板里找到。
  - A7 面板按键和 `/anvil` 命令按 D9 工作。
  - A8 主输入框上方常驻翻译输入框：写中文、按 Enter，英文译文追加到主输入框末尾，中文和焦点留在翻译框；Shift+Enter 换行，中文输入法可用。
  - A9 翻译失败时显示原因、保留中文，再按 Enter 重试；`/config` 里能在订阅模型和自有 API 之间切换；`/anvil translate` 在当前会话切换翻译框的显示和隐藏。
- 非目标：
  - 经典渲染、内联面板、随宽度切换的多种布局；终端窄于 110 列时引擎自行把面板放成内联，不另做设计。桌面端、移动端的界面。
  - 跨 harness（`docs/out-of-scope/cross-harness.md`）；拦截主输入框提交做翻译（`docs/out-of-scope/submit-interception.md`）。
  - 5 分钟 TTL 的探测或兜底；预测时间以外的缓存失效（切模型、切 thinking、服务端提前淘汰）。
  - cache-tax 的 always 和"冷写后自动开 3 小时"；给 mod 供数据的 statusline（"数据泵"）。
  - 翻译的讲解、取消、中英对照历史。
  - 设计中删掉或不做的显示项：会话时长、单轮回执、会话框、上一轮、保活续期记录、缓存读写数量、事件流水、请求次数、干活/空闲、权限模式、advisor、loops、图标的纯文本回退。

## 2. Decisions

### D1：缓存状态只由 anvil 自己估算，一律按 1 小时 TTL

- 过期时刻 = 最后一次主会话请求的时刻 + 1 小时；保活读数达标时，以该次请求的时刻续期。子 agent 的请求不计入。
- 恢复会话时，以引擎在 `classic.SessionStart` 给出的 `prompt_cache_likely_expired`、`seconds_since_last_response`、`context_tokens` 起步；压缩后到下一次响应前不判过期；`/clear` 后清零重来。
- 重建量 = 上下文输入侧 + 上一条回复的输出（k0t.2 结论 4：只算输入侧会偏低）。
- 为什么：statusline 已定取消（k0t.10），mod 又拿不到 Claude Code 自己的缓存追踪器（AGENTS.md Pitfalls）。TTL 一律按 1 小时、不为 5 分钟设计探测或兜底，是用户的裁定（k0t.5 评论，2026-10-12）。别人发的 fork、内置 cache keepalive 的续期 anvil 看不到，估算因此偏保守，代价是守卫偶尔误报、多发一次保活请求，可以接受（k0t.2 误差表）。

### D2：金额按 API 牌价折算

- 过期代价、已重建、守卫提示里的金额，按当前模型的牌价折算（缓存写入用 1 小时写入价）；用量框的"花费"直接取 Claude Code 报的会话花费（`/cost` 同源），上一条消息的花费取两次读数之差。
- 为什么：订阅下实际扣的是额度，缓存读写怎么折算进 5h/7d 额度没有文档（k0t.2 material 6/7）；牌价是唯一可比的尺度，statusline 原本也是这样折算的。

### D3：缓存保活的规则

- 两层分工（用户 2026-10-13 定）：`/config` 的自动开启只决定默认——开着时，上下文达到阈值（默认 5 万 token，与守卫共用）的会话自动开启；阈值和自动开启都在 `/config` 里改（D9）。`/anvil keepalive` 切换本会话的实际状态，不受自动开启和阈值限制：本会话没切换过时按默认；运行中（已启用、进行中）时敲一次关掉，已关闭、未启用或已停下（三种停下任一）时敲一次就在本会话开启并重新开始这一段空闲的保活（用户 2026-10-13 定）。
- 本会话的开关只作用于当前会话，不跨会话记忆。用户关掉后缓存框显示"已关闭（本会话）"，不算下面说的"停下"；手动开启后不再看阈值，停下的规则照旧。
- 只在空闲时工作：空闲快满 1 小时时发一次 `$.model.fork` 请求，读一遍缓存且不进对话记录；提示词要求极短回复（fork 不能设输出上限）。
- 每次请求都检查自身读数：读到的量接近上下文、写入少于读数的 10%，算续上（cache-tax 的判据）。
- 保活自己停下有三种情况：一段空闲续满 12 小时；读数不达标（没读到主会话缓存，或写入过多）；请求出错。停下后缓存框显示"已停止（原因）"，前一种灰、后两种红（D10）。停下只结束这一段空闲：用户回来发消息后，下一段空闲照常保活（用户 2026-10-13 定）。
- 不做 always，也不做"冷写后自动开 3 小时"。
- 缓存框只显示保活状态：已启用、进行中、未启用（自动开启已关闭）、未启用（上下文低于阈值）、已停止（原因）；本会话手动开启时写"已启用（本会话）""进行中（本会话）"，手动关闭时写"已关闭（本会话）"。状态措辞以设计稿的状态对照画板为准，画板上没有的（自动开启已关闭、本会话手动开启）用最直白的写法。
- 代价：每次请求约等于读一遍整段上下文再加少量输出，计入订阅额度；Claude Code 必须开着。内置 cache keepalive 是否开启只影响效率，不改这套规则（k0t.8）。

### D4：冷发送守卫的规则

- 默认开启，`/config` 里可关（D9；开关由用户 2026-10-13 定）。缓存已过期（D1）且上下文达到阈值时，在 `prompt.submit` 把用户的下一条消息 drop 一次，drop 原因就是提示行；原文留在主输入框（drop 后引擎不保留原文时，用 `$.prompt.fill` 放回），用户再按 Enter，这条就放行。
- 只拦用户自己发给模型的消息：斜杠命令和插件发起的提交直接放行。压缩之后、`/clear` 之后不拦。
- 提示行文案（数值按 D1、D2 计算）：「anvil：缓存已过期 1h10m，发送这条消息要重建 152k tokens（约 $3.04）。消息已放回主输入框，再按 Enter 即发送；不需要这段上下文时，可用 /clear 开始新会话。」
- 和否决方向的区别：守卫只拦下、不改写消息，与 `docs/out-of-scope/submit-interception.md` 否决的提交拦截翻译不是一回事。

### D5：翻译输入框的用法

- 常驻在主输入框上方的 AbovePrompt band；用 ctrl+x tab 或点击进入，Esc 回主输入框（引擎的固定键位，mod 不能设全局快捷键）。
- 写中文 → Enter 翻译 → 译文另起一行追加到主输入框末尾（主输入框已有文字且末尾不是换行时先补一个换行；为空或末尾已是换行时不补）→ 用户在主输入框里检查、修改、发送。只追加，不替换；要清空主输入框，用 Claude Code 自带的 ctrl+c 或 ctrl+u。
- Shift+Enter 换行，中文输入法可用（k0t.4 用户实测，推翻了类型注释里"单行"的说法）。
- 中文留在框里，直到用户开始写下一句；写入后焦点留在翻译框（mod 没有办法把焦点交回主输入框）。
- 追加成功后框里的中文没改时，再按 Enter 不做事（不再翻译、不再追加；同一句追加两遍几乎一定是误按，k0t.29）；改了中文再按 Enter 照常翻译、追加。
- 失败时显示原因、中文保留，再按 Enter 重试；不做取消（一句约 1 秒）。
- 翻译框显示：示例和按键提示、正在翻译、已追加 N 个词、失败原因加"按 Enter 重试"。
- `/anvil translate` 在当前会话切换翻译框的显示和隐藏。

### D6：翻译后端

- 两种后端并列，都可选，不分优先：订阅模型（`$.model.complete`，默认 Haiku，可选 Sonnet）；自有 API，只支持 OpenAI 兼容格式（接口地址、key、模型名），走 `$.http.fetch`。
- 后端、订阅模型、自有 API 的接口地址和模型名都在 `/config` 里选（D9）；key 放环境变量 `ANVIL_TRANSLATE_API_KEY`，不进设置（`--plugin-dir` 加载时插件配置的敏感项能否写入未证实，k0t.1）。
- 只输出译文，不附讲解；中文里夹的代码、路径、英文术语原样保留。

### D7：布局只做全屏这一种，statusline 取消

- 左边是对话，右边停靠 anvil 面板（请求宽度约 70 列，用户拖动过的宽度优先），主输入框上方是翻译输入框，而不是放进面板。
- 面板自上而下：缓存、用量、子 agent、自动模式拒绝、我的消息（占满剩余高度），最下面两行是身份栏，贴着面板底边，占原 statusline 的位置（用户 .22 实测后 2026-10-13 定，取代原先"越常看的越靠近输入框"的倒序）。宽度变化时内容在同一布局里排开。
- 空列表不显示（学 flightdeck，取代原先"选定的内容一律常驻"）：子 agent、自动模式拒绝在本会话还没有内容时整个框不画，有了第一条才出现；我的消息一直显示，没有消息时框里一行提示。缓存、用量、身份栏一直显示。
- 面板默认常驻：会话开始时 anvil 自己打开；引擎因宽度门槛没有放下时（自开要求不少于 144 列，AGENTS.md Pitfalls），在用户下一次提交消息时再开，这时算用户请求，110 列即可停靠。
- 留一个开关应付特殊情况：`/anvil panel` 在当前会话切换面板的显示和隐藏（用户 2026-10-13 定）。用户手动关掉面板等同隐藏，本会话不再自动打开，再敲 `/anvil panel` 重新打开。
- statusline 取消：它的内容全部并入面板，其中"本会话改动行数"改成 git 统计（D8）。使用验收通过后，由交付收尾时从用户设置里删掉 `statusLine`，脚本文件保留（§3）。

### D8：面板显示的内容

- 身份栏第一行：
  - 目录名：在 git 里取主仓库目录名；在 linked worktree 中接 worktree 目录名；在子目录中接相对路径，如 `anvil/hooks`；不在 git 里取当前目录名。
  - 分支：分离 HEAD 时显示 `@提交号`，没有上游时标"无上游"。
  - ↑N 领先、↓N 落后；=N 冲突、+N 已暂存、!N 已修改、?N 未跟踪；储藏数。
  - 未提交改动行数 +A −D：工作区和暂存区相对 HEAD 的 git 统计，不是本会话 AI 的改动。
  - git 命令停在一半时显示"暂停图标 + 命令名"，如 ⏸ merge、⏸ rebase 2/5（nf-fa-pause U+F04C）。
  - git 信息由 anvil 自己运行 git 取得。
- 身份栏第二行：模型、effort、输出速度 tok/s（从首字算起，只算主会话）。
- 缓存框、用量框是"名称 + 一行值"两列，一件事一行。成对的值一律"本会话"在前、"上一条"（上一条消息）在后（用户 2026-10-13 定）。
- 缓存框：上边框右侧是"● 有效 · HH:MM 过期"或"○ 已过期 时长"；四行：
  - 命中率：本会话 N% · 上一条 N%。
  - 过期代价：重建 N tokens ≈ $。
  - 已重建：本会话 N 次（有过重建时接" · 共 $"）。
  - 保活：状态（D3）。
  - 还没有任何主会话请求时，命中率、过期代价、已重建的数值写"—"，不写像算出来的 0。
- 用量框四行：
  - 5h、7d：进度条 百分比 · 重置时刻；5h 会在重置前用尽时接" · 预计 HH:MM 用尽"；窗口还没开始时写"发送消息后开始计时"。
  - 上下文：已用 / 上限 (百分比) · 已压缩 N 次，如 `49k / 1M (5%) · 已压缩 0 次`。
  - 花费：本会话 $ · 上一条 $。
- 三个列表都是旧的在上、新的在下；超出上限时顶部显示"▴ 更早的 N 条 · 按键展开"；展开一个列表时其余收成一行（没有内容的不画）。
  - 子 agent：序号、状态（运行中 / 已完成 / 出错 / 输出被截断）、任务、模型、耗时；按序号键展开详情（任务、执行、最近调用、回答）。
  - 自动模式拒绝：时间、工具、命令或路径摘要（遮掉密钥）；选中后显示完整内容和来源（主会话，或子 agent 及第几步）。
  - 我的消息：序号 + 内容；按 Enter 让对话滚到这条消息。
- 列表高度：子 agent、自动模式拒绝收起时框高固定，最多显示最近 3 条，更早的收进顶部"▴ 更早的 N 条"一行；不满 3 条时下面留空，条数变多框也不长高，不把我的消息和其他框挤出去。按序号键展开一个子 agent 的详情时框临时长高放下详情，收起详情后回到固定高度。按 a / d 展开时用我的消息让出的空间、占满剩余高度，其余列表收成一行；Esc 收起后回到固定高度。我的消息收起时占满剩余高度，放不下时顶部写更早的条数。

### D9：按键、命令与设置

- 按键：先用 ctrl+x tab 或点击面板获得焦点；1–9 展开对应子 agent，a / d / m 分别展开子 agent、自动模式拒绝、我的消息列表；↑↓ 移动；Enter 展开详情，选中的是消息时让对话滚到该消息；Esc 收起并回主输入框。
- 命令与设置的分法（用户 2026-10-13 定）：临时的、只管本会话、屏幕上看得到的做命令，长期设置只放 `/config`，两边不重复。
- 只作用于当前会话的命令都是切换，敲一次切一次，回一行新状态（如"面板已隐藏（本会话）"）：`/anvil panel` 显示/隐藏面板，`/anvil translate` 显示/隐藏翻译框，`/anvil keepalive` 开/关本会话的保活（D3）。子命令后面多了词（含未发布的旧写法 `hide|show`、`off|on`）按未知子命令处理。`/anvil` 不带参数列出三个子命令和它们在本会话现在的状态。新会话回到默认（显示面板、显示翻译框、保活按默认）。
- `/config` 的六项设置不做命令；冷发送守卫不做本会话命令。
- 设置用插件清单的 `userConfig` 声明，出现在 Claude Code 的 `/config` 菜单里，也可以 `/config anvil.<项>=<值>` 改；值存在用户 settings.json 的 `pluginConfigs` 里。共六项：
  - 保活与守卫共用的阈值：数字，默认 50000。
  - 自动开启保活：开关，默认开。
  - 冷发送守卫：开关，默认开。
  - 翻译后端：在 haiku、sonnet、api 中选，默认 haiku。
  - 自有 API 的接口地址、模型名：文本，默认空；key 读环境变量（D6）。
- 为什么不用 `$.store`：mods 文档写明，连续 `cleanupPeriodDays`（默认 30 天）没有会话读写它，就会被清掉，设置会悄悄回到默认；有设置的 mod（flightdeck 等）也都用 `userConfig`。（2026-10-13 用户曾改为 `/anvil set` 加 `$.store`，核实清理规则后定回 `/config`。）

### D10：样式

- 视觉以设计稿为准：https://claude.ai/artifact/6TLQhLgvHAYWawkuhmq229 （Version 32；五个画板：工作中、隔夜返回缓存已过期、展开自动模式拒绝、状态对照、身份栏 Git 与配色）。以下是它定下的规则；2026-10-13 的面板改版（D7 的顺序和空列表、D8 的各框内容和列表高度、本节的两列与定宽）与设计稿冲突处以本 spec 为准。
- 整屏只用终端背景一种底色。各区块是圆角边框框，标题嵌在上边框里，右上角是计数或状态；引擎不支持把标题嵌进边框时，退成框内第一行。翻译框用同一套边框样式。
- 识别色：缓存青、用量蓝、子 agent 粉、拒绝红、我的消息中性；识别色避开状态色。
- 用 Nerd Font 图标（用户各台电脑都装了），图标后面一律留一个空格。
- 用量框和缓存框共用两列：名称 8 格 | 值（列间 1 格），名称一列定宽对齐。
- 数值用定宽字段、右对齐，数字变长变短时同一行后面的字不左右跳：百分比 4 格（到 100%），金额 6 格（到 $12.34），tokens 4 格（152k、1.2M），上下文的"(百分比)"6 格；一行末尾的数值和次数不补空格。进度条定宽 15 格（约 51 列停靠时 7d 带星期的重置时刻也排在同一行）。
- 宽度不够时，值按块整块折到下一行（从值那一列起，名称一列空着），不截断、不加"…"（anvil-k0t.31）。
- 变色：进度条四档（低于 60% 绿，60–80% 黄，80–90% 橙，90% 以上红），进度条后的百分比和上下文的百分比同色；effort 五档；命中率低于 80% 变黄、低于 50% 变红；已过期时重建量变红；保活已停止，出错为红、空闲到上限为灰；金额、时长、tok/s 不着色。状态都配符号或文字，不只靠颜色。
- 用词：一个意思只用一个词（过期、上一条消息、上下文、主输入框）；成对值里"上一条消息"简写成"上一条"；消息和拒绝记录用"条"，子 agent 用"个"；时长写作 47s / 2m41s / 1h10m；模型写 Haiku、Sonnet、Opus 5.5。标签直白，不用 flightdeck 那种容易误读的 "main"。

### D11：先验证技术前提，不成立就交还用户

- 下列前提在依赖它的功能动工之前先在交互会话里验证：
  - fork 保活能续上主会话缓存（D3）。
  - 翻译框持有焦点时，`$.prompt.fill` 能真实写入主输入框，不被 `dialog` 拒绝（D5）。
  - drop 之后原文是否还留在主输入框（D4；不留就用 fill 放回，已定）。
  - tok/s 能从首字算起（D8）。
  - Enter 能让对话滚到对应消息（D8）。
  - Pane 能否把标题嵌进上边框（D10；不能就退成框内第一行，已定）。
- 没有预定退路的前提不成立时，停下交用户定，不自行换机制或删功能（Rulings：用户没确认的功能、选项、界面一律不加）。见 Open questions。

### D12：测试接缝

- 缓存状态、保活、守卫是同一块按时间推进的状态，用 mock clock 和模拟事件（`turn.step`、`turn.complete`、`classic.SessionStart`、`session.compact`、`prompt.submit`、fork 的返回值），通过 `claude plugin test` 测；做法沿用 cache-tax 的 mock clock 测试。
- 面板和翻译框的绘制，在 plugin test 的终端 surface 上按几种宽度测：区块齐全、顺序正确、不裁切、不重叠，各状态都有覆盖。
- 翻译后端用替身代替 `$.model.complete` 和 `$.http.fetch`。主输入框的写入只验证接线，真实效果由 D11 的实测证明。

## 3. Verification

- agent：
  - 缓存状态（D1）：过期时刻和续期、恢复会话时的起步、压缩和 `/clear`、子 agent 请求不计、重建量含上一条输出、金额按牌价（D2）。
  - 保活（D3）：达到阈值自动开启、低于阈值不开、`/config` 改阈值、关掉自动开启后生效、本会话切换（自动开启关掉、低于阈值时也能开，默认开着时切一次就关）且新会话回到默认、空闲快满 1 小时发请求、读数达标续期；三种停下（12 小时上限、读数不达标、出错）各自的原因和颜色，以及回来发消息后下一段空闲照常保活；每种状态在缓存框里的显示。
  - 守卫（D4）：过期且达到阈值时拦一次、原文在主输入框、重发放行、提示行数值正确；斜杠命令和插件提交放行；未过期、低于阈值、压缩后、`/clear` 后、`/config` 关掉守卫时都不拦；恢复会话时按 `prompt_cache_likely_expired` 拦。
  - 设置（D9）：六项设置没改时取默认值，`/config` 改过的值传到各功能。
  - 显示（D7–D10）：在请求宽度和拖宽、拖窄后的几种宽度下，面板区块齐全、顺序正确、不裁切不重叠，子 agent、自动模式拒绝没有内容时不画、有内容后框高固定，我的消息占满剩余高度、身份栏贴底，数值变长变短时同一行后面的字不挪位置；缓存有效/已过期、保活各种状态（含本会话手动开、关）、列表超出上限与展开、子 agent 四种状态、身份栏的 git 各种情况（分离 HEAD、无上游、worktree、子目录、不在 git 里、命令停在一半）都有断言；按键和 `/anvil` 命令改变对应状态；面板用 `/anvil panel` 隐藏或手动关掉后本会话不再自动打开，再敲一次重新打开。
  - 翻译（D5、D6）：成功时译文追加、中文保留、显示词数；失败显示原因、Enter 重试；`/config` 切换后端，两种后端各自的请求（OpenAI 兼容格式、key 从环境变量读）；`/anvil translate` 切换显示和隐藏。
  - 静态检查：插件 validate 通过、类型检查无错。检查命令见 `.forge/config.md`。
- human gates（都在用户自己的交互会话里做；按 Rulings 不并行派发；试用步骤只列要验证的几项，并先核对用户环境）：
  - D11 的实测：agent 准备最简的验证手段和步骤，用户执行并回报数字或现象。保活那项回报 ping 的读写数和下一条消息的读写数；写入主输入框那项在翻译框持有焦点时做。
  - 使用验收，一次，按 A1–A9 一张清单：其中离开超过 1 小时后回来，第一条消息命中缓存；关掉保活的会话过期后，第一条消息被守卫拦下；面板与设计稿、`/usage`、`/cost`、`git status` 对照；日常写几条中文，译文写入主输入框。
  - statusline 退役不另设人工节点：使用验收通过后，交付收尾时由 agent 从用户设置里删掉 `statusLine`，脚本文件保留；被权限拦下就请用户手动删。
- review：各实现任务在自己的会话里写测试、跑检查；全部实现完成后做一次独立 review，Spec 轴对照本 spec 的 D 和 §1，Standards 轴对照仓库约定，并检查三项需求共用的部分：缓存状态在守卫、保活、缓存框三处用法一致，面板与翻译框同屏不冲突。
- 不验证：5 分钟 TTL、API key 或云 provider 下的行为；桌面端和移动端；内置 cache keepalive 与 anvil 保活叠加时的效率；真实的 12 小时连续保活（只在 mock clock 下验证上限）。

## Constraints

- Claude Code 2.1.296 的 mods 接口仍是早期版本；以当前构建生成的类型 `.claude-plugin/types/claude-code/index.d.ts` 为准，类型与用户实测冲突时以实测为准（Rulings）。
- 用户环境：Windows Terminal；本机是全屏渲染（环境变量 `CLAUDE_CODE_NO_FLICKER=1` 优先于 settings 的 `"tui": "default"`）；用户在多台电脑上用，终端宽度不固定，各台都装了 Nerd Font；订阅套餐（主会话缓存 TTL 1 小时只在套餐内成立）。
- 引擎限制：面板停靠要求全屏且不少于 110 列，mod 自开要求不少于 144 列；钩子执行上限 10 秒，`prompt.edit` 50 毫秒；`$.store` 本机所有会话共享、非原子、上限 4 MiB；`$.http.fetch` 单次 30 秒、不流式；`$.model.complete` 不流式；`/clear`、`/resume`、`/branch` 会重置 `$.state` 且不触发 `session.start`。
